# 압박 면접 스킬

기술 주제를 주면 면접관 셋이 번갈아 압박 질문을 하고, 끝나면 복기 문서를 만들어 주는 Claude Code 스킬이다. 주제는 숨겨 둔 영역 지도로 나뉘고, 영역마다 가정을 바꾼 질문으로 열어 꼬리질문은 한 번까지만 한다(이 묶음을 줄기라고 부른다). 질문 수는 정해져 있지 않다. 사용자가 '끝'이라고 하거나 Claude가 근거를 대고 끝낼 때까지 한다. 서버나 데이터베이스 없이 Claude Code 명령줄(`claude -p`)만으로 돈다. 저장소 뿌리의 앱(`README.md`)과 같은 면접 엔진을 옮긴 것이고, 앱과 기억을 따로 쓴다.

## 필요한 것

- Claude Code **명령줄** `claude`. 구독(claude.ai) 계정으로 로그인돼 있어야 한다. 데스크톱 앱만 설치했다면 명령줄을 따로 설치해야 한다.
- Node 24.
- 엔진은 `claude`를 셸 없이 띄운다. 지원하는 것은 네이티브 설치기가 깐 `claude.exe`(Windows)나 `claude`다. Windows에서 npm으로 설치해 실행 파일이 `.cmd` 실행기(`claude.cmd`)인 경우는 셸 없이 띄울 수 없어 `cli_missing`으로 끝난다. 아래 "설정" 절의 `claudeCommand`를 `["node", "<npm 전역 폴더>/node_modules/@anthropic-ai/claude-code/cli.js"]`처럼 node와 패키지의 CLI 스크립트로 두는 방법이 있을 수 있지만, **확인하지 못함**이다.

## 설치

`~/.claude/skills/pressure-interview`를 이 저장소의 `plugin/skills/pressure-interview`로 잇는다. 저장소를 고치면 스킬에 바로 반영된다.

```
# Windows (cmd)
mklink /J "%USERPROFILE%\.claude\skills\pressure-interview" "<저장소>\plugin\skills\pressure-interview"

# macOS, Linux
ln -s "<저장소>/plugin/skills/pressure-interview" ~/.claude/skills/pressure-interview
```

새 세션을 열고 `/pressure-interview`를 친다. 처음에는 면접 기록을 둘 폴더를 묻는다.

## 쓰는 법

| 사용자가 치는 것 | 하는 일 |
|---|---|
| `/pressure-interview <주제>` | 새 면접을 시작한다 |
| `/pressure-interview` | 상태: 진행 중인 면접, 다시 연습할 주제, 최근 면접과 id |
| `/pressure-interview 이어서` | 진행 중인 면접을 이어 한다. 열린 질문을 다시 보여 주고, 실패해 멈춘 곳이 있으면 거기서부터 한다. 끝났는데 복기가 안 만들어진 면접이면 복기를 만든다 |
| `/pressure-interview 끝` | 지금 면접을 끝내고 복기를 만든다 |
| `/pressure-interview 복기 [면접 id]` | 끝난 면접의 복기 문서를 만든다 |
| `/pressure-interview 고침 <질문 번호> <잘답함/흔들림/틀림> [면접 id]` | 가정 결과를 고치고 기억을 다시 맞춘다 |
| `/pressure-interview 표시 <질문 번호> <예상/예상밖> [면접 id]` | 예상 표시를 남긴다 |
| `/pressure-interview 추이` | 추이 문서를 다시 만들어 보여 준다 |

- **질문이 열려 있는 동안 보내는 메시지는 모두 답이다.** 되묻는 말이든 "모르겠습니다"든 그대로 엔진에 넘어간다.
- 끝내려면 '끝'이라고만 보낸다. 공백을 빼고 정확히 `끝`일 때만 끝내기로 보고(답 파일에는 저장하지 않는다), 다른 말은 답으로 넘어간다. 끝내면 묻지 않고 같은 명령에서 복기까지 만든다.
- 면접은 한 번에 하나만 진행할 수 있다. 진행 중인 면접이 있는데 새 주제를 주면 `confirm_replace`로 하던 면접을 끝내고 새로 시작할지 묻는다. 그렇다고 하면 진행자가 `start --topic '<주제>' --replace`를 실행하고, 하던 면접은 복기 없이 끝난다(나중에 복기하면 끝낸 까닭이 "새 면접을 시작하며 끝냄"으로 보인다). 아니라고 하면 `이어서`를 한다. 이 대화에서 사용자의 대답은 면접의 답이 아니다.
- 시작이 실패하면 면접이 남지 않는다. 같은 주제로 다시 시작한다.
- 복기, 고침, 표시는 id를 생략하면 가장 최근에 끝난 면접에 한다. 고침과 표시는 복기가 끝난 면접에만 한다.

## 호출과 한도

- 질문마다 모델 호출이 5~6회 나간다: 질문 문장, 흘림 검사, 가정을 바꾼 질문이면 전제 검사, 정답지 작성, 정답지 검증, 답 분석.
- 줄기가 닫힐 때마다 끝내기 판정이 1회 더 나간다. 시작할 때 주제 지도 1회가 더 나간다. 질문을 다시 만들거나 되묻기가 있으면 그만큼 더 나간다. 복기는 답한 질문마다 1회다.
- 질문 수가 정해져 있지 않아 한 판의 호출 수도 판마다 다르다. 이 흐름에서 실제로 잰 값은 **아직 재지 않음**이다.
- 아래 두 측정은 이전 방식(질문 수를 6으로 고정, 줄기와 판정 없음)의 값이다. 지금 흐름의 값이 아니다.
- 이전 방식, 앱의 실제 한 판(질문 6)은 35회 + 복기 6회였다.
- **구독 한도를 쓴다.** API 키를 쓰지 않는다. 엔진이 `ANTHROPIC`·`CLAUDE`로 시작하는 환경 변수를 지우고 `claude`를 부르고, 시작할 때 구독 로그인인지 확인한다. 호출마다 출력 상한은 `CLAUDE_CODE_MAX_OUTPUT_TOKENS=16000`(앱과 같은 값)으로 준다.
- 이전 방식, 스킬의 실제 한 판(2026-11-18, 주제 Redis, 질문 6, 되묻기 1번, 각 1회 측정)은 면접 38회 + 복기 6회였다. 토큰은 면접과 복기를 합쳐 출력 89,488, 캐시 쓰기 202,370, 캐시 읽기 169,467, 캐시 밖 입력 100이었다(엔진의 호출 기록). 가장 큰 몫은 정답지 작성과 검증, 복기다.
- 이 한 판이 구독 한도의 몇 %인지는 재지 못했다(`/usage`의 앞뒤 값이 없다).
- 답을 보낸 뒤 다음 질문까지 엔진이 잰 대기는 30.7~100.0초(평균 63.3초)였다. 이 판은 질문이 뜬 뒤 10~15초 만에 답한 것이라, 앞 질문의 정답지 작성과 검증(둘을 합쳐 평균 77.6초, 질문을 보여 준 뒤에 뒤에서 돈다)이 끝나기를 기다린 시간이 들어 있다. 정답지가 이미 있었던 두 번은 30.7초와 37.4초였다. 진행자 세션이 답을 넘기고 질문을 보여 주는 데 7.8~18.9초가 더 든다(계산값).
- 복기는 102.9초가 걸렸다(호출 6회가 셋씩 두 묶음).
- 한도에 걸리면 엔진은 다시 부르지 않는다. 한도가 풀린 뒤 `이어서`로 멈춘 곳부터 한다.

## 끝내는 규칙

누가 끝내든 끝나면 묻지 않고 같은 명령에서 복기까지 만든다. 끝낸 까닭은 면접 중에 말하지 않고 복기 맨 위에 쓴다.

- 사용자가 끝낸다: 메시지가 정확히 '끝'이다.
- Claude가 끝낸다: 줄기가 닫힐 때마다 `endJudge` 호출이 근거 장부(줄기마다 점수, 신호, 인용)만 보고 `볼 만큼 봤다`(enough), `더 물을 게 없다`(exhausted), `판단이 섰다`(settled), `계속한다`(continue) 가운데 하나를 낸다. 앞의 셋은 코드가 장부에서 조건을 다시 세고, 안 맞으면 계속한다. 셋 모두 핵심 영역을 다 물어야 한다.
- 안전장치: 질문이 `questionCap`(기본 30)에 닿으면 `kind: cap`으로 묻는다. '계속'이면 상한을 30 늘리고(`continue`), 그 밖의 말이면 끝낸다(끝낸 까닭은 안전장치). 이 대답은 면접의 답이 아니다.
- 상한의 숫자와 판정의 문턱은 출발값이고 실제 모델로 맞춰 본 적이 없다.

## 숨긴 폴더

정답지와 질문 의도는 면접 폴더의 `interviews/<면접>/hidden/`에 저장된다. **면접이 끝나기 전에는 열지 않는다.** 열면 보이고, 연습이 안 된다. 오류의 원문은 그 면접의 `hidden/errors.log`에 쓰고, 면접이 생기기 전에 실패한 시작은 면접 폴더 뿌리의 `errors.log`에 쓴다. 둘 다 면접 중에는 열지 않는다. 진행자(모델)도 이 폴더를 읽지 않게 지시해 두었지만, 지시로만 막은 것이라 실제 한 판에서 확인해야 한다.

## 권한 창

기본 권한 모드에서는 답 하나마다 파일 쓰기 한 번(답 파일)과 명령 실행 한 번(엔진)에 권한을 물을 수 있다. 아래 허용 규칙을 `~/.claude/settings.json`의 `permissions.allow`에 넣으면 묻지 않는다. 스킬은 설정 파일을 고치지 않는다. 직접 넣어야 한다.

```json
{
  "permissions": {
    "allow": [
      "Bash(node \"<스킬 폴더>/scripts/cli.mjs\" *)",
      "PowerShell(node \"<스킬 폴더>/scripts/cli.mjs\" *)",
      "Edit(//c/<면접 폴더의 경로>/interviews/**/answers/*)"
    ]
  }
}
```

- `<스킬 폴더>`는 `~/.claude/skills/pressure-interview`를 풀어 쓴 경로다. Bash와 PowerShell 도구가 별개의 규칙이라 둘 다 적는다. 끝의 ` *`는 어떤 인자든, 인자가 없는 경우까지 맞는다.
- 파일 쓰기는 `Write(...)` 규칙이 아니라 `Edit(...)` 규칙으로 묶인다. 공식 문서가 `Write(경로)` 규칙은 맞지 않는다고 하고, `Edit` 규칙이 파일을 고치는 내장 도구 전체에 적용된다고 한다.
- 경로는 gitignore 꼴이다. `//`로 시작하면 파일 시스템 뿌리에서의 절대 경로다. Windows는 경로를 POSIX 꼴로 바꿔 맞추므로 `C:\Users\나\면접`은 `//c/Users/나/면접`이다. macOS·Linux는 `Edit(//<면접 폴더의 절대 경로>/interviews/**/answers/*)`나 홈 아래라면 `Edit(~/<홈 아래 경로>/interviews/**/answers/*)`로 쓴다. 맨 앞 `/` 하나는 설정 파일 위치 기준의 상대 경로라 절대 경로가 아니다.
- 권한 창에서 "Yes, and don't ask again"을 고르면, 명령(Bash)은 저장소와 명령마다 계속 유지되고(`.claude/settings.local.json`에 저장) 파일 수정은 세션이 끝날 때까지만 유지된다.

확인하지 못함:

- 따옴표 안의 경로가 든 명령(`node "<스킬 폴더>/scripts/cli.mjs" <명령>`)을 위 규칙이 맞추는지는 공식 문서에 없다. 규칙이 안 맞으면 권한 창이 뜬다. 그때 창에서 허용하거나 규칙의 꼴을 고친다.
- 세션의 작업 폴더 밖에 있는 면접 폴더에 `Edit` 허용 규칙만으로 쓸 수 있는지도 문서에 없다. 문서가 정한 방법은 면접 폴더에서 세션을 시작하거나, 그 폴더를 작업 폴더로 추가하는 것이다.

## 설정

`~/.pressure-interview/config.json`(없으면 처음 부를 때 만든다). 적은 항목만 바뀌고 나머지는 기본값이다. 홈 폴더를 바꾸려면 환경 변수 `PRESSURE_INTERVIEW_HOME`을 쓴다.

| 항목 | 기본값 | 뜻 |
|---|---|---|
| `dataDir` | 없음 | 면접 기록을 두는 폴더. `setup --data-dir`가 정한다. 절대 경로나 `~`로 시작하는 경로만 받는다 |
| `questionCap` | 30 | 안전장치. 질문이 이 수에 닿으면 이어 할지 묻는다. `계속`이면 30개씩(고정) 늘려 이어 간다. 1 이상의 정수 |
| `maxConsecutive` | 2 | 같은 면접관이 이어서 물을 수 있는 횟수 |
| `maxRegenerations` | 1 | 질문을 다시 만드는 횟수 |
| `reissueAfterHours` | 24 | 다시 연습할 가정을 다시 내기까지 기다리는 시간(시간 단위) |
| `reviewConcurrency` | 3 | 복기 호출을 동시에 도는 수 |
| `callTimeoutMs` | 180000 | 호출 하나의 시간 상한(ms) |
| `pollMs` | 300 | 정답지 뒤 작업을 기다릴 때 확인 간격(ms) |
| `claudeCommand` | `["claude"]` | 부르는 명령과 앞 인자. 셸 없이 띄우므로 `.cmd` 실행기는 쓸 수 없다("필요한 것" 절) |
| `keepEnv` | `[]` | 지우지 않고 남길 환경 변수 이름 |
| `calls.<종류>` | 아래 | 호출 종류별 `model`과 `effort`(low, medium, high, xhigh, max) |

`calls` 기본값: `jobRole` sonnet/medium, `question` opus/medium, `leak` sonnet/low, `premise`·`answerKey`·`verify`·`analyze`·`clarify`·`topicMap` opus/medium, `review`·`endJudge` opus/high. 종류별로 일부만 적어도 합쳐진다.

## 문제가 생기면

```
node "<스킬 폴더>/scripts/cli.mjs" doctor
node "<스킬 폴더>/scripts/cli.mjs" doctor --call
```

설정 파일, 면접 폴더, `claude`의 버전(`claude --version`, 모델 호출 아님)과 로그인을 점검한다. `--call`은 모델 호출을 한 번 더 시험하며 한도를 조금 쓴다. 실패의 `code`와 뜻:

| code | 뜻 |
|---|---|
| `bad_config` | 설정 파일을 읽지 못했거나 값이 틀렸다 |
| `bad_args` | 명령이나 인자가 맞지 않다 |
| `cli_missing` | `claude` 명령을 띄우지 못했다. 설치와 `claudeCommand`를 확인한다 |
| `not_logged_in` | 구독(claude.ai) 로그인이 아니다 |
| `interview_open` | 진행 중인 면접이 있다(동시에 시작한 경우에만. 보통은 `confirm_replace`로 묻는다) |
| `legacy_interview` | 예전 방식의 면접이라 이어 할 수 없다. '끝'으로 끝내고 새로 시작한다 |
| `no_interview` | 해당하는 면접이 없다 |
| `no_answer` | 답 파일이 없거나 비었다 |
| `finished` | 이미 끝난 면접이다 |
| `not_finished` | 끝나지 않은 면접이라 복기할 수 없다 |
| `not_reviewed` | 복기가 끝나지 않아 고침·표시를 할 수 없다 |
| `not_reviewable` | 그 번호의 질문은 고치거나 표시할 수 없다 |
| `not_found` | 그 id의 면접이 없다 |
| `memory_sync_failed` | 가정 기억을 맞추지 못했다. `복기`를 다시 한다 |
| `usage_limit` | 사용 한도에 걸렸다. 풀린 뒤 이어서 한다 |
| `refused` | 모델이 응답을 거절했다. 다시 하면 멈춘 곳부터 한다 |
| `schema_failed` | 응답이 정해진 모양과 맞지 않았다. 같다 |
| `timeout` | 호출이 시간 상한을 넘었다. 같다 |
| `other` | 그 밖의 오류. 같다 |

엔진은 실패한 모델 호출을 스스로 다시 부르지 않는다. 다시 할지는 사용자가 정한다. 원래 오류 문장은 출력에 나오지 않는다. 그 면접의 `hidden/errors.log`에, 면접이 생기기 전에 실패한 시작은 면접 폴더 뿌리의 `errors.log`에 쓰인다. 둘 다 면접 중에는 열지 않고, 면접이 끝난 뒤에 열어 본다.

## 개발

