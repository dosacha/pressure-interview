## 1. 의도

본인이 쓰는 개인용 기술 면접 연습 도구다. 주제를 고르면 시니어 패널이 꼬리질문으로 압박 면접을 하고, 끝나면 복기한다. **[결정]**

성공 기준 **[결정]**
- **S1** 생각지 못한 질문이 들어와도 당황하지 않고 답해 내는 힘.
- **S2** 기술의 장단점이 "왜" 그런지 다시 생각해 보는 계기.

당황의 원인 **[결정]**: 생각지도 못한 가정을 들어 비교를 묻는 질문. 예: "인메모리로 도는 PostgreSQL이라면 Redis와 뭐가 다를까요?"

좋은 대처 **[결정]**: 기술 고민 전에 면접관의 질문 의도부터 빠르게 파악하는 것.

이 도구가 단련하는 것 (위 결정에서 정리)
1. 예상 밖 가정 변경 질문에 대응하기
2. 질문 의도와 반응 의도 읽기
3. 장단점이 생기는 원인을 되짚기

## 2. 목표, 비목표, 실패 조건

**목표**
- 한 판 안에 예상 밖 가정 변경 질문이 들어간다.
- 면접 중에는 실제 면접처럼 진행하고, 배움은 복기에서 일어난다.
- 면접을 거듭해도 같은 가정은 반복되지 않는다. 흔들렸던 가정은 다른 각도로 다시 만난다.

**비목표 (이번 범위 밖)**
- 2단계 프로젝트 기반(서류 입력). 1단계에서는 서류를 받지 않는다. **[결정]**
- 음성. 답변은 전부 텍스트다. **[결정]**
- 코딩 테스트. 1단계만이 아니라 도구 전체에서 뺀다. 인수인계 문서의 "교과형에 코딩 테스트 포함"과 "코딩 테스트도 풀이를 말로 설명"을 대체한다. **[결정]**
- 로그인, 다중 사용자. **[제안, 인수인계 문서]** DB는 2026-11-16 결정으로 비목표에서 빠졌다(3장).
- 면접 중 피드백이나 가르치기. 의도 숨김과 해답 흘리지 않기 결정에서 따라 나온다.

**실패 조건 [결정]**
- **F1** 한 판 내내 모든 질문이 뻔하다. 질문 하나가 뻔한 것은 괜찮다.
- **F2** 면접관이 내가 언급하지 않은 대안 기술이나, 그 기술이 문제를 푸는 특징을 면접 중에 알려 준다.
- **F3** 면접관이 쥔 대안 지식이 틀리다. 사용자의 말: "면접관은 이 내용을 정확히 알고 있어야 한다."

**도출한 실패 조건 [제안]**
- **F4** 복기가 틀려서 잘못된 지식이나 잘못된 신호 읽기를 배운다.

## 3. 제약

- 개인 PC(Windows)에서 본인 한 명이 쓴다.
- Claude API를 쓴다. `ANTHROPIC_API_KEY`가 필요하고, Claude Code 구독과 별도로 과금된다. **[인수인계 문서의 제안]**
- **기술 스택 [결정, 2026-11-16 변경]**: 사용자의 BlueGang 프로젝트와 같은 스택을 쓴다. 이전의 "Node 서버 + HTML 한 장 + JSON 파일 저장"[제안]을 대체한다.
  - 언어 TypeScript, 백엔드 NestJS, ORM TypeORM, DB PostgreSQL, 화면 React + Vite + Tailwind. **[결정]**
  - PostgreSQL은 이 프로젝트 전용 Docker compose, 포트, 볼륨으로 띄우고, 다른 프로젝트의 DB를 함께 쓰지 않는다. **[제안, 사용자 작업 지침의 자원 격리]**
  - 버전과 도구 설정은 BlueGang main 브랜치(1ea20e8, 2026-10-16)에 맞춘다. Node ≥24.21, NestJS 11, TypeORM 1.x, PostgreSQL 18, TypeScript 5.9, Jest 30 + ts-jest, ESLint 10 + typescript-eslint 8, Prettier 3, React 19, Vite 8, Tailwind 4다. **[제안]**
  - Claude 호출은 `@anthropic-ai/sdk`로 한다. **[제안, claude-api 기준]**
- 모델은 호출 종류(분석, 질문, 정답지 검증, 복기)마다 설정에서 바꿀 수 있게 한다. 기본값은 정확도를 우선해, 정답지 검증과 복기에 상위 모델을 쓴다. 면접마다 사용량을 복기에 보여 줘서, 써 본 뒤에 예산을 정할 수 있게 한다. **[제안]**

## 4. 접근 방식

| 방식 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **1. 분석 → 규칙 → 한 명만 질문** **[결정: 선택]** | 분석 호출로 답변의 결함을 찾고, 코드 규칙으로 다음 질문자와 반응 의도를 정한 뒤, 뽑힌 한 명이 질문을 쓴다 | 점수 뭉침이 없다. 선택 근거가 복기에 남는다. 면접관 목소리가 섞이지 않는다. 턴당 호출 2회 | 결함 → 담당, 결함 우선순위 규칙을 직접 만들어야 한다. 규칙이 딱딱하면 패턴이 읽힌다 |
| 2. 전원 동시 반응 → 채택 | 면접관마다 별도 호출로 결함, 반응 의도, 질문 초안을 낸 뒤 규칙으로 하나를 채택한다 | 관점이 독립적이다. 2등 초안이 덧붙이기 재료가 된다 | 턴당 호출이 면접관 수만큼 든다. 초안 대부분이 버려진다. 판정끼리 모순될 수 있다 |
| 3. Claude Code 스킬로만 운영 | 앱 없이 대화 안에서 진행한다 | 구독 안이라 추가 비용이 없다. 만들 것이 가장 적다 | 숨긴 의도가 도구 결과에 비칠 수 있다. 답 시작 시간을 잴 수 없다. 그래서 탈락 |

방식 1을 고른 이유: 이미 정한 것들(의도 숨김 후 복기 공개, 결함과 성향으로 질문자 결정, 오판은 복기에서 바로잡기)과 가장 곧게 맞물리고, 호출이 가장 적다.

인수인계 문서에서 재검토 대상이던 "방식 B(판정 호출 + 질문 호출)"가 이 형태로 되살아난다.

## 5. 패널

### 5.1 면접관 = 직무 × 성향

- 유형은 직무형, 교과형, 시나리오형 세 가지다. **[결정]**
- 교과형은 "학부 전 과목 시험 항상 100점" 수준을 전제한다. 범위는 네트워크, 메모리, OS, 컴퓨터 구조, 자료구조, 알고리즘, 창의력이고, 모두 개념 질문으로 묻는다. 코딩 테스트는 없다. **[결정]**
- 성향은 직무와 따로 두고, 면접마다 섞는다. **[결정]**
- 면접관의 정의 **[제안]**: 직무는 "주로 바꾸는 가정 축"과 "주로 확인하는 질문 의도"를 정한다. 성향은 "즐겨 쓰는 반응 의도"를 정한다.
- 서류 정보 비대칭 **[결정]**: 면접관은 서류(이력서, 포트폴리오, README)까지만 읽고 코드는 읽지 않는다. 기술 지식은 시니어 수준으로 완벽하다고 전제한다. 1단계에는 서류가 없으므로, 직무형은 내 답변 속 주장을 서류 대신 쓴다. **[제안]**

직무 표 **[제안. 직무 목록은 사용자가 아직 정하지 않음]**

| 면접관 | 주로 바꾸는 가정 | 주로 확인하는 것 |
|---|---|---|
| DBA (직무형) | 영속성·전달 보장, 일관성, 데이터 분포 | 원리 이해, 한계 인식 |
| 보안 (직무형) | 공격, 장애 양상 | 장애·부분 실패 |
| 아키텍트 (직무형) | 기술 대체, 비용, 요구 변경 | 선택 근거, 대안 시야, 복잡도가 꼭 필요한지 |
| 교과형 | 자원 한도, CS 원리의 전제 | 원리 이해, 지식 경계 |
| 시나리오형 | 규모, 분포, 지연 예산 | 규모 적응, 극단 분포 |

- 직무형 세 가지(DBA=정합성/영속성, 보안=장애/공격, 아키텍트=대안 비교)는 사용자가 든 예다. 보안 행은 조사 자료가 없어서 Claude가 추론했다.

성향 3종 **[제안]**

| 성향 | 즐겨 쓰는 반응 의도 |
|---|---|
| 집요형 | 상향 심화, 반례 재질문 |
| 조력형 | 누락 신호, 방향 넛지, 맥락 보충 |
| 흔드는형 | 확신 시험, 수용성 시험 |

패널 구성 **[제안]**: 면접마다 3명을 둔다. 직무형 1명(주제에 맞는 직무), 교과형 1명, 시나리오형 1명이고, 성향은 무작위로 배정한다.

### 5.2 의도 목록

- 의도는 두 층이다. 질문 의도는 "이 질문으로 무엇을 확인하나", 반응 의도는 "직전 답변에 어떻게 반응하나"다. **[제안]**
- 사용자가 익힐 수 있도록 유한하고 이름이 붙은 목록으로 둔다. **[제안. 성공 기준에서 도출]**
- 초안은 research 파일의 질문 의도 15개(A1–A15)와 반응 의도 11개(B1–B11)다.
  - 사용자가 든 반응 의도 예 ① 잘하네, 이것도 알까? ② 놓친 것 같은데 모르는 건가? ③ 설명이 애매하네 ④ 틀렸네, 표현을 바꿔 재질문은 각각 B1, B4, B2, B6에 대응한다.
  - 확신 시험(B8)은 후보다. 기술 면접 쪽 근거가 약하다. **[제안]**
- 복기에서 보여 줄 묶음 **[제안]**

| 층 | 묶음 | 포함 |
|---|---|---|
| 질문 의도 | 깊이 | A1 원리 이해, A14 지식 경계 |
| | 판단 | A2 선택 근거, A3 대안 시야, A4 트레이드오프, A12 복잡도의 필요성 |

### 5.3 가정 변경

- 압박의 핵심은 예상 밖 가정 변경 질문이다(당황의 원인에서 나옴). **[결정]** 말투나 타이머 같은 연출은 질문 품질보다 뒤로 둔다. **[제안]**
- 가정 변경은 세 유형이 공통으로 쓰는 기법이고, 유형마다 바꾸는 축이 다르다(5.1 표). **[제안]**
- 좋은 가정 변경은 장단점을 만드는 원인 하나를 바꿔서, 무엇이 사라지고 무엇이 남는지 묻게 만든다. **[제안]**
- 가정 축 어휘 **[제안]**: 규모, 자원 한도, 데이터 분포, 장애 양상, 일관성 완화, 영속성·전달 보장, 요구·규제 변경, 기술 대체, 비용, 지연 예산, 시간·조직(research 파일).
  - 여기에 "기술의 핵심 속성 바꾸기(정체성 비교)"를 더한다. 사용자가 당황했던 유형인데, 공개 자료에서 사례를 찾지 못했다.
- 한 판에 가정 변경 질문을 최소 1개 보장한다(F1 방지). **[제안]**

## 6. 면접 한 판

### 6.1 시작

- 주제를 고른다(예: Redis, NodeJS, 자료구조). **[결정]** 주제는 자유롭게 입력한다. **[제안]**
- 주제가 중심이다. 교과형은 주제에서 이어지는 CS 기본기로 내려갈 수 있다. 예: Redis → 이벤트 루프 → I/O 다중화 → OS. **[제안]**
- 패널을 구성하고(5.1), 기억(8)에서 후보 가정을 준비한다.
- 첫 질문은 주제의 기본 질문이어도 된다. 질문 하나가 뻔한 것은 괜찮기 때문이다(F1).
- 사회자는 두지 않는다. 시작과 마무리는 패널 중 한 명이 맡는다. **[제안]**

### 6.2 턴 (방식 1)

1. **질문을 표시한다.** 질문 의도는 숨긴다. **[결정]** 답을 쓰기 시작할 때까지 걸린 시간을 측정한다. 질문 표시부터 첫 입력까지다. **[제안]**
2. **사용자가 되묻거나 답한다.**
   - 되묻기를 허용한다. 같은 면접관이 질문의 범위와 조건까지만 답하고, 의도는 말하지 않는다. 성향과 상관없이 같은 방식이다. **[결정]**
   - 되묻기를 썼다는 사실은 기록한다. **[제안]** 되묻기와 답변을 어떻게 구분할지는 builder에게 맡긴다.
   - 답 첫머리에 의도를 짚는 습관을 화면 안내로 권한다. **[제안]**
3. **분석 호출로 답변의 결함 유형을 찾는다.** 결함 유형 초안 **[제안]**: 오답 의심 / 축 누락(어느 직무 축인지) / why 없음 / 트레이드오프 누락 / 모호함 / 근거 없음 / 결함 없음(강한 답). 출발점은 research 파일의 "결함 → 꼬리질문" 표(K4)다.
4. **규칙(코드)으로 다음 질문자와 반응 의도를 정한다.** **[제안]**
   - 사용자가 정한 "반응이 가장 강한 면접관이 다음 질문을 한다"를 "우선순위가 가장 높은 결함을 맡은 면접관이 질문한다"로 해석한다. 모델이 매긴 점수로 경쟁시키지 않는다.
   - 결함 우선순위 초안: 오답 의심 > 축 누락 > why·트레이드오프 누락 > 모호함·근거 없음 > 결함 없음(상향 심화). 써 보면서 조정한다.
   - 축 누락은 그 축을 맡은 면접관에게 간다. 축이 없는 결함(오답 의심, 모호함 등)은 답변 내용과 가장 가까운 축의 면접관에게 간다. 직전 질문자가 자동으로 이어받는 규칙은 쓰지 않는다. **[결정: 제외됨]**
   - 반응 의도는 그 면접관의 성향으로 고른다. 예: 같은 축 누락이라도 집요형은 반례 재질문, 조력형은 누락 신호.
   - 같은 면접관이 연속으로 질문하는 횟수에 상한을 둔다(쏠림 방지).
   - 가정 변경 질문 최소 보장(5.3)을 함께 적용한다.
   - 동시 질문은 사용자가 정한 "동시 또는 번갈아"를 따른다. **[결정]** 상위 결함 두 개를 서로 다른 면접관이 맡고 둘 다 우선순위가 높을 때만, 두 번째 면접관이 "저도 하나 덧붙이면…" 하고 얹는다. 질문 호출이 2회가 되고, 드물게 쓴다. **[제안]**
   - 끼어들기는 긴 답변의 앞 문장 하나만 붙잡고 반응하는 식으로 흉내 낸다. 우선순위는 낮다. **[제안]**
5. **질문 호출**: 뽑힌 면접관 한 명이 질문과 숨은 정답지(6.4)를 쓴다.
6. **정답지 검증 호출** **[제안]**
   - 가정 변경 질문처럼 질문 문장 안에 기술 사실이 전제로 들어가는 경우에는, 질문을 보여 주기 전에 전제를 검증한다. 틀린 전제가 화면에 나가면 F3가 면접 중에 그대로 보이기 때문이다. 그 턴의 대기 시간은 늘지만, 답 시작 시간 측정에는 영향이 없다.
   - 그 밖의 질문은 사용자가 답을 쓰는 동안 정답지를 검증한다. 검증에서 정답지가 고쳐지면 이후 반응과 복기에는 고친 정답지를 쓰고, 복기에 "정답지 수정됨"을 표시한다.
   - 이미 나간 질문의 전제가 나중에 틀린 것으로 드러나면, 면접 중에는 그대로 두고 복기에 표시한다.
7. **면접 중 판정 오류는 허용한다.** **[결정]** 면접 중에는 피드백하지 않는다.

### 6.3 기술 이름 규칙 [결정]

- 먼저 꺼내도 되는 기술: 내가 먼저 말한 기술, 서류에 있는 기술(2단계), 가정 변경의 전제로 쓰는 기술. 마지막은 내가 써 보지 않은 기술이어도 된다.
- 금지: 내 문제의 해답 후보인데 내가 언급한 적 없는 기술, 그리고 그 기술이 문제를 푸는 특징.
- 사용자가 든 예시
  - X: "이러한 기술은 왜 고려하지 않으셨나요?"
  - X: "이러한 기술도 이런 특징으로 해결할 수 있는데 알고 계셨나요?"
  - O: "사용하신 기술 말고 다른 대안은 없었을까요?"
  - O: "대안이 있었다는 걸 아셨는데 왜 그 기술을 사용했나요?"
- 인수인계 문서의 예시 "Redis 대기열을 썼는데 Kafka는 고려해 보셨나요?"는 Kafka가 내 답변(또는 2단계 서류)에 나왔을 때만 성립한다.
- 위반은 생성할 때 지시하는 것만으로 부족할 수 있어서 생성 후 검사가 필요할 수 있다. 방법은 builder에게 맡기고, 시험 대상으로 둔다(11).

### 6.4 숨은 정답지 [제안. F3에서 도출]

질문마다 다음을 만든다.
- 질문 의도
- 바뀐 가정(축과 구체 내용)
- 그 가정에서 사라지는 차이와 남는 차이
- 고려할 만한 대안 기술과 그 특징
- 기대하는 답의 핵심

면접 중에는 숨기고 복기에서 공개한다. 판정(틀려도 됨)과 달리 정답지는 정확해야 한다.

### 6.5 종료

- 질문 수 상한에 도달하면 끝난다. 상한값은 써 보며 정한다. "볼 만큼 봤다"는 조기 종료 조건은 써 보면서 추가한다. **[제안]**
- 마무리는 패널 중 한 명이 한다.

## 8. 기억과 반복 방지 [결정: 가정별 복기 결과를 기억]

- 반복의 단위는 질문 문장이 아니라 바뀐 가정이다. **[제안]**
  - 가정 = 축(5.3의 닫힌 목록) + 구체 가정(기술과 무관한 한 문장, 예: "저장 매체가 메모리가 된다").
  - 기술 쌍은 단위에 넣지 않는다. "다른 기술 조합에 끼워 다시 낸다"는 결정이 성립하려면, 기술이 바뀌어도 같은 가정으로 알아봐야 하기 때문이다.
  - 같은 가정인지는 같은 축 안에서 모델이 비교해 판별한다.
  - "잘 답함"은 그 구체 가정만 은퇴시키고, 축 전체를 은퇴시키지는 않는다.
- 잘 답한 가정은 다시 내지 않는다. 흔들렸거나 틀린 가정은 시간을 두고 다른 기술 조합에 끼워 다시 낸다. **[결정]** "시간을 두고"의 간격은 builder에게 맡긴다.
- 흔들린 가정은 사용자가 고른 주제와 이어질 수 있을 때만 다시 낸다. 면접 시작 화면에, 다시 연습할 가정이 남아 있는 주제를 보여 준다. **[제안]**
- 가정별 결과는 답의 내용만으로 가른다. 힌트를 받았든 아니든, 최종적으로 맞게 답했으면 "잘 답함"이다. **[결정]**
  - "흔들림"은 일부만 맞은 답(핵심 차이 일부 누락), "틀림"은 핵심이 틀린 답으로 본다. 분류는 복기 재검사가 한다. **[제안]**
  - 판정 한 번으로 가정이 은퇴하므로, 사용자가 복기에서 판정을 고칠 수 있게 한다. **[제안]**
- 사용자의 "예상했음" 표시도 반복 판단에 쓴다. **[제안]**
- 시작 난이도는 따로 설정하지 않는다. 면접 중에는 반응 의도(상향 심화)로 올라가고, 면접과 면접 사이에는 기록에서 출발한다. **[제안]**

## 11. 남은 위험
