# pressure-interview

신입 개발자의 기술 압박 면접을 혼자 연습하는 Claude Code 스킬.

기술 면접에서 나를 가장 당황하게 한 건 모르는 개념이 아니었다. 생각지도 못한 가정을 세워 놓고 비교를 묻는 질문이었다. "인메모리로 도는 PostgreSQL이라면 Redis와 뭐가 다를까요?" 같은 것. 이런 질문 앞에서는 기술을 고민하기 전에 면접관이 무엇을 보려고 묻는지부터 빨리 읽어야 한다. 이 감각은 혼자 책을 읽어서는 잘 늘지 않는다.

그래서 이 도구로 연습하는 것은 셋이다.

1. 예상 밖의 가정 변경 질문에 대응하기
2. 질문 의도와 면접관의 반응 의도 읽기
3. 장단점이 생기는 원인을 되짚기

**pressure-interview는 그 연습 상대다.** 주제 하나를 주면 면접관 셋이 번갈아 꼬리질문으로 압박한다. 다음 질문은 내 답의 빈 곳과 틀린 곳을 따라 정해지고, 면접관은 때로 기술의 장단점을 만드는 가정 하나를 바꿔 묻는다. 누가 다음에 물을지, 무엇을 숨길지는 모델이 아니라 스킬에 든 Node 스크립트(아래에서 "엔진")가 정한다.

**면접 중에는 정답을 알려 주지 않는다.** 질문 의도와 숨은 정답지는 파일에 따로 두고 대화에는 내지 않는다. 스킬을 부른 Claude 세션은 엔진이 준 질문을 그대로 보여 주고 내 답을 엔진에 넘기기만 한다(아래에서 "진행자"). 실제 면접처럼 진행하고, 무엇을 놓쳤는지는 끝난 뒤 복기에서 배운다. 복기는 질문마다 숨겼던 의도와 정답지, 면접 중 판정이 맞았는지 다시 검사한 결과를 보여 준다.

**약한 곳만 다시 묻는다.** 흔들렸거나 틀린 가정은 기억해 뒀다가 다음 면접의 면접관에게 넘긴다. 면접관은 주제와 이어지면 그 가정을 다른 기술 조합으로 다시 묻는다. 잘 답한 가정은 다시 내지 말라고 지시한다.

**서버도 API 키도 없다.** Claude Code 세션 안에서 돈다. 모델 호출은 구독 계정으로 로그인한 `claude` 명령줄로 나가고, 띄울 서버나 데이터베이스가 없다.

## 설치

필요한 것:

- Claude Code **명령줄** `claude`. 구독(claude.ai) 계정으로 로그인돼 있어야 한다. 데스크톱 앱만 설치했다면 명령줄을 따로 설치한다.
- Windows에서는 네이티브 설치기로 설치한 `claude.exe`여야 한다. npm으로 설치해 `claude.cmd`만 있으면 엔진이 `claude`를 실행하지 못한다(자세한 것은 [`plugin/README.md`](./plugin/README.md)의 "필요한 것").
- Node.js 24. 엔진은 의존성이 없어서 `npm install`이 필요 없다.

저장소를 내려받고, 저장소 안의 `plugin/skills/pressure-interview` 폴더를 `~/.claude/skills/` 아래에 링크로 건다.

```bash
git clone https://github.com/dosacha/pressure-interview.git
cd pressure-interview
```

Windows (PowerShell):

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\.claude\skills" | Out-Null
New-Item -ItemType Junction -Path "$env:USERPROFILE\.claude\skills\pressure-interview" -Target "$PWD\plugin\skills\pressure-interview"
```

macOS, Linux:

```bash
mkdir -p ~/.claude/skills
ln -s "$PWD/plugin/skills/pressure-interview" ~/.claude/skills/pressure-interview
```

Claude Code를 새로 열면 `/pressure-interview`가 보인다. 복사본이 아니라 링크로 걸었기 때문에, 저장소를 `git pull`하면 스킬도 바로 바뀐다.

`/plugin install`로는 아직 설치할 수 없다. 폴더 구조만 플러그인에 맞춰 뒀다.

설치가 맞는지는 저장소 뿌리에서 이렇게 본다. `--call`을 붙이면 모델을 한 번 불러 본다.

```bash
node plugin/skills/pressure-interview/scripts/cli.mjs doctor
node plugin/skills/pressure-interview/scripts/cli.mjs doctor --call
```

## 시작하기

두 단계다.

1. 새 세션에서 주제를 주고 시작한다. 처음 한 번은 면접 기록을 둘 폴더(아래에서 "면접 폴더", 설정의 `dataDir`)를 묻는다. 숨은 정답지도 이 폴더에 저장되니 저장소 밖의 폴더(예: `~/pressure-interview`)를 고른다. 저장소 안에 두면 정답지가 커밋에 섞일 수 있다.

   ```
   /pressure-interview Redis
   ```

2. 질문 6개가 끝나면 진행자가 복기를 만들지 묻는다. "네"라고 답하거나 아래 명령을 친다.

   ```
   /pressure-interview 복기
   ```

기본 권한 모드에서는 답마다 권한 창이 두 번 뜰 수 있다. 줄이는 법은 아래 "권한 창"에 있다.

그게 전부다. 복기 문서(`review.md`)는 면접 폴더의 `interviews/<면접>/` 아래에 생긴다.

## 쓰는 법

주제는 자유롭게 쓴다. 기술 이름 하나여도 되고 상황이어도 된다.

```
/pressure-interview Redis
```

```
/pressure-interview 공연 티켓 예매 창에 트래픽이 몰릴 때 재고 정합성을 지키는 방법
```

- **질문이 열려 있는 동안 보내는 메시지는 모두 답이다.** 되묻는 말이든 "모르겠습니다"든 그대로 엔진에 넘어간다.
- 되물어도 된다. 같은 면접관이 질문의 범위와 조건까지만 답한다.
- 면접관이 꺼낸 기술을 모른다고 하면 캐묻지 않고 넘어간다. 모른다고 한 기술의 이름은 다시 꺼내지 않게 검사한다.
- 면접은 한 번에 하나만 진행한다. 멈추려면 `/pressure-interview 끝`을 친다.

| `/pressure-interview 표시 <질문 번호> <예상/예상밖> [면접 id]` | 그 질문을 예상했는지 표시한다 |

## 한 판은 이렇게 돈다

### 면접관 셋

면접마다 직무형 한 명, 교과형 한 명, 시나리오형 한 명을 둔다. 직무형은 주제에 맞춰 DBA, 보안, 아키텍트 가운데 하나를 고른다. 성향(집요형, 조력형, 흔드는형)은 셋에게 무작위로 붙는다.

| 면접관 | 주로 바꾸는 가정 | 주로 확인하는 것 |
|---|---|---|
| DBA (직무형) | 영속성·전달 보장, 일관성 완화, 데이터 분포 | 원리 이해, 트레이드오프·한계 인식 |
| 보안 (직무형) | 공격, 장애 양상 | 장애·부분 실패 |
| 아키텍트 (직무형) | 기술 대체, 비용, 요구·규제 변경, 시간·조직 | 선택 근거, 대안 시야, 복잡도의 필요성 |
| 교과형 | 자원 한도, CS 원리의 전제 | 원리 이해, 지식 경계 |
| 시나리오형 | 규모, 데이터 분포, 지연 예산 | 규모 적응, 극단 분포 |

"기술의 핵심 속성 바꾸기(정체성 비교)"는 셋 모두가 쓴다. 맨 위의 PostgreSQL 질문이 이 유형이다.

| 성향 | 하는 것 | 쓰는 반응 |
|---|---|---|
| 집요형 | 더 깊이 파고들고 반례로 되묻는다 | 상향 심화, 반례 재질문, 근거 요구, 누락 신호, 구체화 요구 |
| 조력형 | 빠진 곳을 짚어 주고 방향을 귀띔한다 | 상향 심화, 누락 신호, 방향 넛지, 맥락 보충 재질문, 근거 요구 |
| 흔드는형 | 확신을 흔들고 반박을 받아들이는지 본다 | 확신 시험, 수용성 시험, 구체화 요구 |

### 답 하나에 일어나는 일

1. **답을 분석한다.** 답에서 결함을 찾는다. 종류는 오답 의심, 축 누락(꼭 짚어야 할 관점을 빠뜨림), why 없음, 트레이드오프 누락, 모호함, 근거 없음이고, 결함이 없다고 볼 수도 있다.
2. **다음 질문자를 코드가 고른다.** 우선순위가 가장 높은 결함(오답 의심 > 축 누락 > why 없음·트레이드오프 누락 > 모호함·근거 없음 > 결함 없음)을 맡은 면접관이 묻고, 반응은 그 면접관의 성향으로 정한다. 같은 면접관이 연달아 물을 수 있는 횟수에는 상한이 있다(모른다고 해서 넘어가는 질문은 예외). 누가 물을지는 모델에게 맡기지 않고 이 규칙으로만 정한다.
3. **그 면접관이 질문을 쓴다.** 판의 절반이 지나도록 가정을 바꾼 질문이 없으면, 엔진이 다음 면접관에게 정체성 비교 축으로 물으라고 지시한다. 모델이 지시를 따랐는지는 따로 검사하지 않는다.
4. **보여 주기 전에 검사한다.** 내가 말하지 않은 해답 기술을 흘리지 않았는지 보고(흘림 검사), 가정을 바꾼 질문이면 그 전제가 기술적으로 맞는지 본다(전제 검사). 걸리면 그 지적을 붙여 질문을 한 번 다시 만든다. 다시 만든 질문도 걸리면 그대로 보여 주고, 복기 문서에 흘림 표시나 전제 표시를 남긴다.
5. **질문을 보여 준 다음,** 내가 답을 쓰는 동안 그 질문의 숨은 정답지를 따로 쓰고 검증한다. 다음 답의 분석은 이 정답지로 한다.

분석, 질문, 검사, 정답지, 복기는 모두 서로의 맥락을 모르는 별도 호출이다. 질문을 쓰는 면접관은 정답지를 보지 않고, 흘림 검사는 질문 문장과 내가 말한 기술만 본다.

### 숨기는 것

질문 의도, 바뀐 가정, 정답지, 결함 판정은 면접 폴더의 `interviews/<면접>/hidden/`에만 저장된다. 엔진의 출력에는 질문 문장만 실린다. 진행자도 그 폴더를 읽지 않게 지시돼 있다.

숨김은 기술로 막은 것이 아니라 약속이다. 그냥 파일이라 열면 보이니, 면접이 끝나기 전에는 직접 열어 보지 않는다. 열면 연습이 안 된다.

## 복기와 기억

복기 문서는 질문마다 이렇게 나뉜다.

- 되묻기가 있었으면 그 내용
- 내 답 (보낸 그대로)
- 질문 의도와 그 질문이 나온 까닭
- 내 답이 의도를 향했는가
- 면접 중 판정의 재검사 (면접 중 판정은 틀릴 수 있다. 복기가 다시 본다)
- 이 답에서 나온 질문 (맞는 지적, 오판, 의도된 확신 시험, 더 깊이 물음 가운데 무엇이었나)
- 바뀐 가정과 정답지, 복기가 정답지에서 찾은 문제
- 흘림 표시와 전제 표시, 예상 표시

맨 위에는 가정별 결과가, 맨 아래에는 호출 기록과 답을 보낸 뒤 다음 질문이 뜨기까지 기다린 시간이 있다.

가정별 결과는 **잘 답함, 흔들림, 틀림** 셋이고, 답의 내용만으로 가른다. 힌트를 받았어도 결국 맞게 답했으면 잘 답함이다. 결과는 면접 폴더의 `memory.json`에 쌓인다.

- 흔들리거나 틀린 가정은 마지막으로 물은 지 24시간이 지나면 다음 면접의 질문 후보로 면접관에게 넘어간다(최대 5개). 면접관은 이번 주제와 이어질 때만 다른 기술 조합으로 다시 묻는다.
- 잘 답한 가정은 최근 30개를 면접관에게 넘겨 다시 내지 말라고 지시한다.
- 판정이 마음에 안 들면 `고침`으로 바꾼다. 기억도 다시 맞춘다.
- `추이`는 최근 면접, 예상 밖이었던 질문의 비율, 흔들림이나 틀림에서 잘 답함으로 바뀐 가정의 수, 다시 연습할 주제를 `stats.md`에 모은다.

## 호출과 한도

**구독 한도를 쓴다.** API 키는 쓰지 않는다. 엔진은 `ANTHROPIC`·`CLAUDE`로 시작하는 환경 변수를 지우고(로그인 위치인 `CLAUDE_CONFIG_DIR`와 설정의 `keepEnv`에 적은 이름은 남긴다) `claude`를 부르며, 시작할 때 구독 로그인인지 확인한다. 아니면 면접을 시작하지 않는다.

- 질문마다 모델 호출이 5~6회 나간다: 질문, 흘림 검사, (가정을 바꾼 질문이면) 전제 검사, 정답지 작성, 정답지 검증, 답 분석.
- 시작할 때 1회 더 나간다. 되묻기 한 번에 3회(답 분석, 되묻기 응답, 흘림 검사), 질문을 한 번 다시 만들 때 2~3회가 더 나간다.
- 복기는 답한 질문마다 1회다.
- 직무 고르기와 흘림 검사는 sonnet, 나머지는 opus로 부른다. effort는 흘림 검사가 low, 복기가 high, 나머지가 medium이다.

아래는 Claude가 다른 세션에서 지원자 역할을 맡아 한 판(질문 6개, 되묻기 1번)을 재 본 값이다. 2026-11-18에 Windows에서 한 번 쟀다.

| 항목 | 값 |
|---|---|
| 호출 | 면접 38회 + 복기 6회, 실패 0 |
| 토큰 | 출력 89,488, 캐시 쓰기 202,370, 캐시 읽기 169,467 |
| 답 보낸 뒤 대기 (엔진이 잰 값) | 30.7~100.0초, 평균 63.3초 |
| 답 보낸 뒤 다음 질문이 보일 때까지 | 47.8~108.1초, 평균 74.5초 |
| 복기 | 102.9초 |

이 판에서는 질문이 뜨고 10~15초 만에 답했다. 그래서 대기의 상당 부분은 앞 질문의 정답지 작성과 검증이 끝나기를 기다린 시간으로 본다(기록으로 계산한 값). 정답지가 이미 있었던 두 번은 엔진 기준 30.7초와 37.4초였다. 사람이 직접 답한 판과 한 판이 구독 한도의 몇 %를 쓰는지는 아직 재지 못했다.

엔진은 실패한 호출을 스스로 다시 부르지 않는다. 한도에 걸리면 풀린 뒤, 면접 중이었으면 `이어서`, 복기 중이었으면 `복기`를 다시 친다. 시작하다 실패했으면 면접이 남지 않으므로 같은 주제로 다시 시작한다.

## 권한 창

기본 권한 모드에서는 답 하나마다 두 번 권한을 물을 수 있다. 답을 파일에 쓸 때 한 번, 엔진 명령을 돌릴 때 한 번이다. `~/.claude/settings.json`에 넣을 허용 규칙은 [`plugin/README.md`](./plugin/README.md)의 "권한 창"에 있다. 스킬은 설정 파일을 고치지 않는다.

## 내 것으로 만들기

설정은 `~/.pressure-interview/config.json`이다. 적은 항목만 바뀌고 나머지는 기본값을 쓴다.

```json
{
  "dataDir": "C:\\Users\\me\\pressure-interview",
  "questionLimit": 8,
  "calls": {
    "question": { "effort": "high" }
  }
}
```

`dataDir`는 처음 부를 때 스킬이 물어서 적는다. 손으로 적을 때는 절대 경로로 적는다(파일 안의 `~`는 풀리지 않는다).

| 항목 | 기본값 | 뜻 |
|---|---|---|
| `questionLimit` | 6 | 한 판의 질문 수(2~30) |
| `maxConsecutive` | 2 | 같은 면접관이 이어서 물을 수 있는 횟수 |
| `reissueAfterHours` | 24 | 흔들리거나 틀린 가정을 다시 내기까지 기다리는 시간 |
| `calls.<종류>` | 위 "호출과 한도" | 호출 종류별 `model`과 `effort` |

나머지 항목과 오류 코드의 뜻은 [`plugin/README.md`](./plugin/README.md)에 있다. 질문을 만드는 프롬프트 자체를 바꾸고 싶다면 아래 "개발"을 본다.

## 왜 서버가 없나?

처음에는 NestJS 서버, PostgreSQL, 웹 화면, Anthropic API 키로 도는 서버판이었다. 서버를 띄우지 않고, API 과금 대신 구독 한도 안에서 쓰려고 스킬로 다시 만들었다. 면접의 규칙과 프롬프트는 서버판과 같다. 달라진 것은 그 규칙을 돌리는 자리뿐이다. 서버판도 이 저장소에 그대로 있다(아래 "서버판").

## 왜 서브에이전트가 아니라 `claude -p`인가?

엔진은 모델 호출마다 `claude -p`(한 번 묻고 끝나는 실행)를 따로 띄운다. Claude Code의 도구(파일 읽기, 명령 실행 등)를 쓰지 못하게 하고, 답의 형식을 정해서 부른다. 호출마다 새 프로세스라서 서로의 맥락을 모른다.

서브에이전트로도 같은 격리를 만들 수 있다. 한 번 재 봤을 때 서브에이전트 하나의 기록은 약 8만 토큰이었고, `claude -p`는 호출당 붙는 토큰이 약 1,300이었다. 서브에이전트의 값이 누적인지는 확정하지 못했고, 도구를 줄인 서브에이전트로는 재지 않았다. 다음 질문자를 고르는 규칙을 모델이 아니라 코드로 지키기에도 스크립트가 낫다.

## 서버판

같은 면접을 웹 화면으로 하는 서버판이다. API 키로 과금된다.

<details>
<summary>서버판 띄우기</summary>

필요한 것: Node.js 24.21 이상, Docker, Anthropic API 키.

```bash
npm install
```

`.env.example`을 `.env`로 복사하고 `ANTHROPIC_API_KEY`를 채운다. 나머지 값을 그대로 두면 서버판은 `127.0.0.1:3110`, DB는 `127.0.0.1:5436`을 쓴다.

```bash
docker compose up -d --wait db
npm run migration:run
npm run start:app
```

브라우저에서 `http://127.0.0.1:3110`을 연다.

- 과금 없이 화면만 보려면 `npm run start:fake`(가짜 모델 응답과 임시 DB, `http://127.0.0.1:3199`).
- 2026-11-17에 질문 6개짜리 면접을 두 번 돌렸을 때, 기록된 토큰 수에 가격표를 곱한 값은 한 판에 약 $1.4~$2.0이었다(청구서가 아닌 계산값, 프롬프트 캐싱을 넣기 전).
- 서버판의 기억을 스킬로 옮기려면 `node tools/import-app-memory.mjs`(DB는 읽기만 한다).

| 명령 | 하는 일 |
|---|---|
| `npm test` | 단위 테스트 |
| `npm run test:e2e` | 임시 PostgreSQL 컨테이너와 가짜 모델 응답으로 도는 e2e |
| `npm run typecheck` | 서버 타입 검사 |
| `npm run lint` | ESLint |
| `npm run frontend:verify` | 화면의 타입 검사, lint, 테스트, 빌드 |

</details>

## 개발

```bash
node --test "plugin/test/**/*.test.mjs"
```

스킬의 테스트는 실제 모델을 부르지 않는다. 가짜 `claude`(`plugin/test/fake-claude.mjs`)와 임시 폴더만 쓴다. 서버판에서 옮겨 온 규칙의 테스트, 시작부터 복기까지의 흐름, 숨길 내용이 면접 중의 출력에 하나도 섞이지 않는지 보는 누출 검사가 들어 있다.

```
plugin/skills/pressure-interview/
  SKILL.md              진행자의 규칙
  scripts/cli.mjs       엔진 명령
  scripts/lib/          설정, 저장, claude 실행기, 면접 진행, 복기
  scripts/lib/app/      서버판에서 옮겨 와 스킬이 고쳐 쓰는 규칙과 프롬프트
plugin/test/            node:test
src/, frontend/         서버판
tools/                  옮기는 도구들
docs/                   설계, 계획, 실제로 돌려 본 기록
```

`scripts/lib/app/`의 규칙과 프롬프트는 서버판(`aeae0dd`)에서 옮겨 왔고 이제 스킬이 직접 고친다. 서버판은 더 고치지 않는다.

## 아직 확인하지 못한 것

- 실제 모델로는 Windows 11, Claude Code 2.1.326의 데스크톱 앱 세션에서 Claude가 지원자 역할로 한 판만 돌려 봤다. 다음은 가짜 실행기 테스트만 있고 실제로 확인하지 않았다.
  - macOS와 Linux
  - 터미널의 `claude` 세션
  - 사람이 직접 친 답
  - `끝`, `복기`, `고침`, `표시`, `추이` 명령 (복기는 진행자에게 말로 요청해 만들었다)
  - 권한 허용 규칙의 효과
  - 대화가 압축된 뒤의 진행
  - 기억이 다음 면접의 질문에 실리는지
- Claude Code가 아닌 도구(Codex, Cursor 등)와 구독 로그인이 아닌 인증(API 키, Bedrock, Vertex)은 지원하지 않는다.
- 한 판이 구독 한도의 몇 %를 쓰는지 재지 못했다.
- 구독 로그인으로 `claude -p`를 스크립트에서 되풀이해 부르는 것이 약관상 괜찮은지 확인하지 않았다.
- 한도, 거절, 시간 초과 같은 실패가 실제로 났을 때의 동작은 아직 본 적이 없다.
- 복기 문장에 내부 이름(`A4`, `p1` 같은 것)이 보일 수 있다.
